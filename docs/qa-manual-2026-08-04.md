# Manual QA — feature’y 04-08-2026

Uproszczona checklista do ręcznego testowania na urządzeniu/emulatorze.  
Cel: wyłapać proste bugi, regresje i problemy UI/UX przed release’em.

---

## Przed startem

| Element | Wymaganie |
|---------|-----------|
| Konto | Zalogowany user z aktywną parą językową (np. PL → ES) |
| Dane | Min. 2 listy użytkownika + lista **Uczę się** + kilka kart w różnych stanach SRS |
| Sieć | Możliwość włączenia trybu samolotowego / wyłączenia Wi‑Fi |
| Uprawnienia | Mikrofon (STT), powiadomienia (Android 13+) — testuj też scenariusz **odmowy** |
| Backend | API dostępne (lokalnie lub staging); dla F4 mock LLM: w notatce zgłoszenia wpisz `accept` |

**Jak oznaczać wynik:** ✅ OK · ❌ bug · ⚠️ UX do poprawy · ⏭ pominięto (brak warunków)

## 1. Full offline

### 1.1 Banner offline na Add
1. Włącz tryb samolotowy (po wcześniejszym syncu online).
2. Otwórz zakładkę **Add**.

**Sprawdź:**
- [ ] Widać banner „Jesteś offline” / „You’re offline” z krótkim opisem.
- [ ] Przyciski importu (plik / wklej) są **wyszarzone** lub zablokowane.
- [ ] Tap na import pokazuje komunikat, że wymaga internetu (nie crash).

### 1.2 Wyszukiwanie offline → Oczekujące
1. Nadal offline: wpisz słowo w pole search (np. `casa`) i wyślij (strzałka).
2. Przejdź do **Lists** → znajdź listę **Oczekujące** / **Pending**.

**Sprawdź:**
- [ ] Słowo pojawiło się na liście Oczekujące.
- [ ] Kafelek jest **wyszarzony** ze statusem **Czeka na sieć** / **Waiting for network**.
- [ ] Nie da się rozwinąć kafelka / nie widać treści fiszki (pending).

### 1.3 Przeglądanie list offline
1. Offline: otwórz **Uczę się** i własną listę z już zsynchronizowanymi kartami.

**Sprawdź:**
- [ ] Listy i słowa ładują się z cache (bez pustego ekranu błędu).
- [ ] Lemma, POS, status SRS widoczne jak online.
- [ ] Rozwinięcie kafelka pokazuje treść (gloss / reveal).

### 1.4 Move między listami offline
1. Offline: na liście użytkownika rozwiń kartę → przenieś do **Uczę się** (ikona move).
2. Przenieś inną kartę z Uczę się na listę użytkownika.

**Sprawdź:**
- [ ] Karta znika z listy źródłowej i pojawia się na docelowej (lokalnie).
- [ ] Brak duplikatu na obu listach.
- [ ] Po powrocie online i syncu stan jest taki sam na serwerze (odśwież listy).

### 1.5 Practice offline
1. Offline: wejdź w **Nauka** / Practice z kartami w kolejce.

**Sprawdź:**
- [ ] Kolejka się ładuje (due + new z cache).
- [ ] Można ocenić kartę (Again/Hard/Good/Easy lub typing/choice).
- [ ] Postęp SRS zmienia się lokalnie (karta przechodzi dalej w sesji).
- [ ] Po powrocie online sync nie gubi ocen (sprawdź tę samą kartę na liście — status się zgadza).

### 1.6 Flush po powrocie online
1. Wróć online (wyłącz tryb samolotowy).
2. Poczekaj na sync (lub zrób pull — wyjdź z apki i wróć).

**Sprawdź:**
- [ ] Karty z **Oczekujące** przechodzą w `pending` → `ready` (lub `failed`).
- [ ] Banner offline znika na Add.
- [ ] Import znowu działa.

### 1.7 Regresja — brak Ulubionych
**Sprawdź:**
- [ ] Nigdzie w UI nie ma zakładki / listy / akcji „Ulubione” / Favorites.

## 2. Listy — filtrowanie i sortowanie

### 2.1 Chip POS na kafelku
1. **Lists** → lista z kartami o znanym POS (np. noun, verb).

**Sprawdź:**
- [ ] Pod lemma widać chip części mowy (np. „rzeczownik” / localized label).
- [ ] Kolor chipu POS **różni się** od chipu statusu SRS (nie ten sam odcień).
- [ ] W trybie jasnym: POS ≈ kremowy, status ≈ zielonkawy (wg planu).
- [ ] W trybie ciemnym: oba czytelne, nadal rozróżnialne.

### 2.2 Chip statusu SRS
1. Przygotuj karty: new, learning, review (&lt;21 dni), mastered (review ≥21 dni).

**Sprawdź:**
- [ ] Etykiety: new / learning / review / mastered (lub PL odpowiedniki).
- [ ] Karta w `review` z krótkim interwałem pokazuje **review**, nie „learning” (znana poprawka).
- [ ] `pending` / `awaiting_network` / `failed` mają właściwe stany (spinner / szary / error).

### 2.3 Sort — modal
1. Na liście z ≥3 kartami tap **Sort** (ikona / przycisk sortowania).

**Sprawdź:**
- [ ] Otwiera się bottom sheet z opcjami sortowania.
- [ ] A→Z / Z→A zmienia kolejność natychmiast po wyborze.
- [ ] Sort po POS, newest, oldest, status — każdy daje sensowną kolejność.
- [ ] Zamknięcie sheeta bez crashu; wybrana opcja zostaje aktywna po ponownym otwarciu.

### 2.4 Filter — modal
1. Tap **Filter** na liście.

**Sprawdź:**
- [ ] Multi-select POS (np. tylko verb) — lista się zawęża.
- [ ] Multi-select status (np. tylko new) — działa.
- [ ] Kombinacja POS + status (AND) — poprawna.
- [ ] **Zastosuj** / Apply zamyka sheet; **Wyczyść** / reset przywraca pełną listę.
- [ ] Zmiana listy (chip listy) **resetuje filtr** (nie zostaje stary filtr z poprzedniej listy).

### 2.5 Pasek meta (aktywny filtr / sort)
**Sprawdź:**
- [ ] Gdy filtr aktywny — widać skrócony opis (ile kart / co filtruje).
- [ ] Tap „wyczyść” na pasku meta działa.

### 2.6 UX — długie listy
1. Lista 20+ kart, sort Z→A + filtr POS.

**Sprawdź:**
- [ ] Scroll płynny, brak migotania chipów.
- [ ] Rozwinięcie jednego kafelka nie psuje sortowania innych.

## 3. Practice — Undo

### 3.1 Widoczność przycisku
1. Wejdź w Practice z niepustą kolejką.
2. Oceń kartę (dowolna ocena).

**Sprawdź:**
- [ ] Po ocenie w TopAppBar pojawia się ikona **Undo** (cofnij).
- [ ] Przed pierwszą oceną w sesji Undo **nie** widać (lub jest nieaktywne).

### 3.2 Cofnięcie jednej oceny
1. Zapamiętaj kartę i ocenę (np. Good).
2. Tap **Undo**.

**Sprawdź:**
- [ ] Wracasz do tej samej karty w fazie oceniania / tyłu fiszki (jak przed oceną).
- [ ] Można ocenić ponownie inną oceną.
- [ ] Undo działa tylko **raz** (drugi Undo nie cofa dalej wstecz — brak stacku).

### 3.3 Undo na ostatniej karcie sesji
1. Dojdź do ostatniej karty w kolejce, oceń.
2. Undo.

**Sprawdź:**
- [ ] Nie lądujesz od razu na ekranie „koniec kolejki” — wracasz do ostatniej karty.
- [ ] Po ponownej ocenie flow końca sesji działa normalnie.

### 3.4 Sync po Undo
1. Online: oceń → Undo → oceń ponownie.
2. Wyjdź z Practice, sprawdź kartę na liście.

**Sprawdź:**
- [ ] Na liście widać **ostateczną** ocenę (po Undo + drugiej ocenie).
- [ ] Brak „podwójnego” review w sync (idempotencja).

### 3.5 Undo offline
1. Offline: oceń → Undo → oceń.

**Sprawdź:**
- [ ] Działa lokalnie bez crashu.
- [ ] Po syncu online stan SRS zgodny z ostatnią oceną.

## 4. Popraw kartę (zgłoszenie + edycja własna)

> Wymaga **internetu**. Do szybkiego testu accepted: w notatce wpisz słowo `accept`.

### 4.1 Wejście z listy
1. **Lists** → rozwiń kartę `ready`.
2. Tap ikonę **edycji / Popraw kartę** (obok delete/move).

**Sprawdź:**
- [ ] Otwiera się bottom sheet „Zgłoś problem” / „Report a problem”.
- [ ] Widać chipy sekcji (lemma, gloss, examples, …).
- [ ] Pole notatki + przycisk Wyślij.

### 4.2 Walidacja formularza
1. Otwórz modal, nic nie zaznaczaj, puste pole → Wyślij.
2. Wpisz tylko `ab` (2 znaki) bez sekcji → Wyślij.

**Sprawdź:**
- [ ] Komunikat walidacji — nie wysyła requestu.
- [ ] Zaznacz ≥1 sekcję LUB notatka ≥3 znaki → wysyłka dozwolona.

### 4.3 Wysłanie zgłoszenia
1. Zaznacz np. **gloss**, notatka: `accept`, Wyślij.

**Sprawdź:**
- [ ] Loading na przycisku, brak double-submit.
- [ ] Sheet się zamyka; na kafelku chip **Zgłoszono poprawkę** / **Correction reported**.
- [ ] Nauka (Practice) nadal działa na tej karcie — **nie** jest zablokowana.

### 4.4 Wynik — accepted (po ~kilku s)
1. Poczekaj na job AI (polling) lub otwórz kartę ponownie.

**Sprawdź:**
- [ ] Dialog: „Zgłoszenie uznane — kartę zaktualizowano”.
- [ ] Treść karty na liście odświeżona (gloss / content).
- [ ] Chip zmienia się na **Poprawiono** / **Updated** (lub znika po czasie — OK jeśli UX tak zaplanowany).

### 4.5 Wynik — rejected
1. Wyślij zgłoszenie **bez** `accept` w notatce (np. „test reject”).

**Sprawdź:**
- [ ] Dialog: zgłoszenie nieuznane + krótki reason.
- [ ] Tekst o możliwości edycji własnej.
- [ ] Przyciski: **Anuluj** | **Edytuj samodzielnie**.

### 4.6 Edycja własna (self-edit)
1. Z rejected dialogu → **Edytuj samodzielnie** (lub otwórz self-edit po reject).

**Sprawdź:**
- [ ] Sheet z polami: lemma, POS, gloss, dodatkowe gloss (wielolinijkowe).
- [ ] Zapisz → sheet zamyka się, karta na liście ma nowe wartości.
- [ ] Chip **Edytowana ręcznie** / **Edited manually**.
- [ ] Karta **zostaje** w tej samej liście i zachowuje postęp SRS.

### 4.7 Wejście z Practice
1. Practice → pokaż tył fiszki (SHOW_CARD).
2. Tap **Popraw kartę** nad przyciskami ocen.

**Sprawdź:**
- [ ] Ten sam flow co z listy.
- [ ] Przyciski Again/Hard/Good/Easy nadal dostępne i nie zasłonięte.

### 4.8 Offline — blokada
1. Offline: spróbuj otworzyć Popraw kartę.

**Sprawdź:**
- [ ] Akcja zablokowana + komunikat „Wymaga internetu”.
- [ ] Brak crashu.

### 4.9 Rate limit (opcjonalnie)
1. Wyślij wiele zgłoszeń pod rząd (&gt;20/dzień).

**Sprawdź:**
- [ ] Backend zwraca 429; apka pokazuje sensowny błąd (nie crash).

## 5. Tryb mówienia — STT (Add)

> Emulator często **nie ma** STT — testuj na fizycznym urządzeniu.

### 5.1 Ikona mikrofonu
1. **Add** → pole search.

**Sprawdź:**
- [ ] Obok strzałki submit widać ikonę **mikrofonu**.
- [ ] Layout nie przepełnia się na wąskim ekranie.

### 5.2 Permission — pierwszy raz
1. Tap mikrofon (świeża instalacja lub po revoke permission).

**Sprawdź:**
- [ ] Systemowy dialog mikrofonu.
- [ ] **Zezwól** → otwiera sheet słuchania.
- [ ] **Odmów** → komunikat, brak crashu; można dalej pisać ręcznie.

### 5.3 Sheet słuchania
1. Zezwól na mic → tap **Start**.

**Sprawdź:**
- [ ] Widać chipy języka: **L2** (domyślnie) i **L1**.
- [ ] Zmiana chipa przed Start zmienia język rozpoznawania.
- [ ] Po wypowiedzeniu słowa (np. „hola”) partial text może się pojawić.
- [ ] **Stop** / zamknięcie sheeta anuluje bez search.

### 5.4 Wynik → lookup
1. Powiedz słowo, poczekaj na finalny wynik.

**Sprawdź:**
- [ ] Tekst trafia do pola search (widać przed wysłaniem).
- [ ] Automatycznie odpala się ten sam flow co Enter/strzałka (kandydaci online).
- [ ] Offline: słowo ląduje w Oczekujące (jak §1.2).

### 5.5 Regresja — ręczne wpisywanie
1. Wpisz słowo klawiaturą, wyślij strzałką.

**Sprawdź:**
- [ ] Działa jak wcześniej; STT nic nie psuje.

### 5.6 Brak STT na urządzeniu
1. (Jeśli możliwe) urządzenie bez Google STT.

**Sprawdź:**
- [ ] Komunikat „Rozpoznawanie mowy niedostępne” — nie crash.

## 6. Push i powiadomienia

### 6.1 Uprawnienie POST_NOTIFICATIONS (Android 13+)
1. Świeża instalacja → **Settings** → sekcja **Powiadomienia**.

**Sprawdź:**
- [ ] Widać toggles: przypomnienia nauki, karty gotowe.
- [ ] Pole godziny przypomnienia (0–23).
- [ ] Jeśli system zablokował notyfikacje — toggles OFF lub komunikat (nie crash).

### 6.2 Zapis ustawień powiadomień
1. Wyłącz/włącz **Przypomnienia o nauce**, zmień godzinę, zapisz (auto-save).
2. Wyjdź z Settings i wróć.

**Sprawdź:**
- [ ] Wartości się utrzymały (sync z backendem po online).

### 6.3 Lokalne przypomnienie nauki (WorkManager)
> Trudne do testu „na teraz” — ustaw godzinę za 2–3 minuty od teraz LUB zmień czas systemowy (ostrożnie).

**Sprawdź:**
- [ ] O ustawionej godzinie (gdy są karty due) pojawia się notyfikacja „Czas na powtórkę” z liczbą kart.
- [ ] Gdy **brak** due — brak notyfikacji (lub soft nudge — zgodnie z implementacją).
- [ ] Tap w notyfikację otwiera apę (deep link opcjonalny — OK jeśli tylko launch).

### 6.4 Karty gotowe (enrichment)
1. Online: dodaj nowe słowo do nauki (status `pending` na liście).
2. Zminimalizuj apę / zabij z recentów, poczekaj na enrichment (FCM lub worker ~30 min).

**Sprawdź:**
- [ ] Notyfikacja „Karty gotowe” / „N słów gotowych” gdy karta przeszła w `ready`.
- [ ] Po wyłączeniu toggle **Karty gotowe** w Settings — brak tej notyfikacji.

### 6.5 Poprawka rozstrzygnięta (F4 + F6)
1. Wyślij zgłoszenie poprawki z apki w tle.

**Sprawdź:**
- [ ] (Gdy FCM skonfigurowany) push „Sprawdzono poprawkę”.
- [ ] Bez FCM: przynajmniej dialog przy ponownym wejściu w kartę.

### 6.6 Kanały powiadomień (Android settings systemowe)
1. Ustawienia systemu → Aplikacje → Vocabulario → Powiadomienia.

**Sprawdź:**
- [ ] Kanały **Study** / **Nauka** i **Cards** / **Karty** istnieją.

## Znane ograniczenia (nie traktuj jako bugów w tej iteracji)

- **FCM na Androidzie** — pełny push wymaga `google-services.json`; bez niego działają lokalne workery.
- **STT na emulatorze** — często niedostępny; test na telefonie.
- **Rate limit poprawek** — 20 zgłoszeń / dzień / user.
- **Konflikt multi-device offline** — LWW bez UI rozwiązywania konfliktów.
- **Import offline** — celowo zablokowany.
